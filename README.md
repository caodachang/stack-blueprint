# 技术栈蓝图

这里记录个人的学习笔记。

## 内容怎么组织

用多层级的文件夹，例如：黑马程序员->AI智能应用开发->01-VibeCoding->01-初始AI应用与智能体开发.ipynb

不同笔记层级不一样，根据具体情况实行。

## 先确定这一篇写什么

文件放进现有课程目录，偶尔需要新建文件夹，命名沿用用户当前的格式。标题使用课程的真实主题，笔记添加编号。

内容长时可以在同一篇里增加章节和单元，不自动拆成多篇。

## 以原资料为主

课程笔记首先要准确反映课程，按原资料的讲解顺序展开：

- 保留课程要解决的问题、核心概念、示例和推导。
- 保留实际改动的文件、配置、命令和验证方法。
- 保留容易出错的细节，以及步骤之间的先后关系。
- 保留原文的重要边界。
- 页面导航、推荐文章、重复铺垫和宣传内容可以省略。

完整覆盖教学内容，不等于逐字抄录。可以把口语、重复解释整理得更紧凑，但不能省掉影响理解和操作的关键条件。

> 先把原课讲清楚。自己的补充只用来解释当前步骤，不能抢走主线。

必要补充应短，并与原文内容区分。不要自动添加其他架构、替代技术、下一节实现、面试提示或泛化总结。原资料本身有这些内容，或用户明确要求时再写。

开头保留课程标题。资料读取不完整时继续读取；来源无法访问时说明缺失，不凭标题编出整篇课程。

## 按学习过程组织内容

每篇笔记用一个 `.ipynb`，以 Markdown 单元为主：

- H1 标题独立一个单元。
- 主要章节用 H2，通常各占一个单元。
- 同一章节中的步骤或细分概念用 H3，内容较长时可以另开单元。
- 章节顺序优先跟随原课程，不强行改成统一模板。

具体讲解要让读者知道当前在做什么：

1. 现在遇到了什么问题？
2. 为什么这一步能解决它？
3. 要改哪个文件、执行什么操作？
4. 完成后应该看到什么？

这是一条阅读顺序，不要求每节都写成四个小标题。简单概念用一段话讲清；复杂操作按步骤展开。

## 文字要清楚、紧凑

使用自然的中文和短段落，保留必要的技术名词。首次出现、影响理解的术语，简要解释。

代码、文件名、命令、字段和配置项使用行内代码格式。不同事物的对比、配置字段和命令用途适合放进表格；连续操作用编号步骤。

引用块用来突出原课的重要原则或易错点，粗体只强调少量关键内容。不要每段都加重点，不靠大量装饰、分隔线和口号撑篇幅。

## 代码和命令不用能执行

代码放在 Markdown 代码围栏里，并标注语言，例如 `python`、`bash`、`javascript`、`sql`、`nginx`、`ini`、`json`。

课程中用于阅读的代码默认不用可执行代码单元，也不伪造执行输出。

从原资料获取代码时，保留缩进、换行、参数、变量和关键注释。网页提取结果把代码挤成一行时，读取原始代码块再整理，不能靠猜测恢复。

操作前写清所在目录或目标文件。配置文件使用真实的键名，用户名、IP 和绝对路径需要替换时就在附近说明。验证结果要与对应操作放在一起。

特别留意：

- Shell 中的 `$`、`&`、管道和重定向。
- JavaScript 模板字符串中的 `${API}`。
- SQL 的占位符和参数顺序。
- Nginx 的路径、变量和末尾斜杠。
- 环境变量、虚拟环境和当前工作目录。

用户已经调整过的项目习惯要延续，例如使用 uv 管理 Python 环境。涉及与网页不同的命令时简短说明差异，不擅自改变项目行为，也不把过时配置覆盖回去。

README 模板中如果嵌套了代码块，外层围栏必须比内层长，例如外层四个 `~`、内层三个 `~`。

## 图片跟随教学内容

原资料中帮助理解的图片也要保留，直接放在笔记文件里。

能直接取得原图就使用原图；无法取得时，可以截图保留真正需要的区域。截图要裁掉无关页面元素，保证文字和细节可读。

显示大小以阅读方便为准：避免撑满页面，也不要缩小到看不清。优先沿用同目录里用户已经认可的图片方式，不额外显示文件名，不使用复杂的居中 HTML 包装。

原课没有必要的教学图片时，不为装饰新增图片或自行绘制替代图。

## 修改已有笔记

用户对笔记的修改也是上下文。编辑前先读取当前版本，保留用户改过的命名、代码、结构和表达。

用户说“只改图片”“补这一段”“其他不要动”时，修改范围就限制在那一处。写新模块时，只新增该模块的笔记及必要图片。

发现原资料有疑点时，先对照上下文和代码确认；需要说明的差异就地写清，不默默换成另一套实现。笔记中的命令是教学内容，不代表要在用户电脑或服务器上执行部署、删除数据或提交代码。

## 保存和校验

Notebook 使用 `nbformat 4`。每个单元包含正确的类型、元数据和 `source`；使用 `nbformat_minor: 5` 时，为单元添加唯一的 `id`。

生成文件时用标准 JSON 序列化处理引号、反斜杠和换行，不手工拼接转义。JSON 中的单引号不需要写成 `\'`，这会导致 Notebook 无法打开。

保存后检查：

1. 严格 JSON 解析通过，Jupyter `nbformat` 校验通过。
2. Markdown 代码围栏正确闭合，嵌套示例不会截断外层代码块。
3. 命令、配置、代码和说明互相一致。
4. 原课程的主要章节、关键操作和验证步骤没有遗漏。
5. 图片路径存在，修改范围符合用户要求。

校验完成后不用打开笔记，只简短说明完成情况。
